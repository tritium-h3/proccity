# Terrain v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace v1 terrain (dense height grid) with polygon terrain. Water carves the
site, Voronoi land cells are classified by a declarative rule table and merged into
regions, every vertex carries an elevation, and each region stores its own constrained
triangulation. Fine detail comes from a TSL node-material shader.

**Architecture:** Pure modules in `src/stages/terrain/`:
- `layout.ts` (water)
- `cells.ts` (Voronoi + graph)
- `rules.ts` (classification + merge)
- `elevation.ts` (levels, vertex and centre elevations)
- `ground.ts` (CDT surfaces)
- `stage.ts` (assembly)

`src/doc/ground.ts` handles surface queries. The renderer (`src/scene/renderers/terrain.ts`)
uses a TSL node material.

**Tech Stack:** as before, plus `d3-delaunay`, `delaunator` and `@kninnug/constrainautor`
(latest).

**Spec:** `docs/superpowers/specs/2026-11-21-terrain-v2-design.md`

## Global Constraints

- Branch `terrain-v2`. Each task ends with a commit, **gated on** `npm run typecheck &&
  npx oxlint src && npm test` (all three must pass before `git commit`), with the trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Merge to `main` locally when
  done. No pushing.
- Elevations are absolute metres above sea level. Slab heights stay above-ground.
- Vertex identity is the coordinate rounded to 1 cm (`vkey(p) = Math.round(x*100)+','+Math.round(z*100)`).
  Shared cell vertices must get identical elevations through this key.
- Partition invariant: terrain children partition the site (`checkPartition`).
- Budgets at 2 km defaults: under 10,000 ground triangles, generation under 100 ms (tests
  assert under 500 and log the actual), scene rebuild under 50 ms.
- Cosmetic shader displacement of at most ±2 m.
- After quick successive edits to a file, run `npm run dev:restart` before browser checks.
- Docs ride along.

## Deviations from the spec (decided while planning)

1. **Triangulation is constrained Delaunay** (`delaunator` + `constrainautor`) over each
   region's boundary points plus interior points, keeping triangles whose centroid lies in
   the footprint. One method serves every region, and it supports the interior points
   (cell centres, river course points, pond centres) that fans and ear clipping can't.
2. **Pond boundary vertices sit at pond surface + 0.5 m (bank), and the pond centre at
   surface − 2 m (bed).** The spec's "vertex takes the pond level" would put the bank exactly
   at the waterline, which contradicts "banks above the surface".

## Review Focus

1. **Shared vertices between neighbouring cells after clipping:** identical keys must give
   identical elevations, with no seams or cracks in the merged mesh. *(Task 5 test: every
   key across all regions maps to one elevation.)*
2. **A tiny or sliver cell** after clipping (under 1 m², or a needle along the river): no
   throw, no NaN elevations, and the partition holds. *(Task 2: clip pieces under 1 m² are
   merged into the neighbour sharing the longest edge, or dropped if isolated.)*
3. **Settings extremes:** cellSize 60 on a 5000 m site (about 7,000 cells; perf logged),
   cellSize 250 on a 500 m site (a handful of cells), flatWidth 0 and 5, ponds 6 with no
   eligible cells. No throw, and the partition holds. *(Task 6.)*
4. **Old v1 cities** (with `heightfield`, without `ground`) open, render the site flat and
   don't throw in `groundHeightAt`. *(Task 1 test.)*
5. **The flat-elevation override on a river flat:** the region becomes level at the override,
   and its bank vertices still sit above the river. *(Task 6 test.)*

### Task 2: Land cells

**Files:** Create `src/stages/terrain/cells.ts` and its test. Install `d3-delaunay`.

**Interfaces:**

```ts
export interface Cell {
  id: number; seed: Point2; poly: Polygon;          // clipped to land, outer ring CCW
  area: number; neighbours: number[];               // shared edge > 1 m
  touchesSea: boolean; touchesRiver: boolean;
  hop: number; nearest: 'sea' | 'river' | 'none';
}
export function buildCells(land: MultiPolygon, site: MultiPolygon, sea: MultiPolygon | null, river: MultiPolygon | null,
  cellSize: number, rng: () => number): Cell[];
export const vkey: (p: Point2) => string;
```

Seeds go on a jittered grid (jitter ±0.35 × cellSize), relaxed by one Lloyd step. Voronoi
comes from `Delaunay.from(seeds).voronoi([minX, minZ, maxX, maxZ])`. Each cell is clipped
by `intersect([cellPoly], land)`, and each resulting polygon becomes its own `Cell`, with
`seed` = the polygon centroid if the original seed fell outside it.

Pieces under 1 m² are unioned into the neighbour sharing the longest edge, or dropped if
isolated (Review Focus 2).

Neighbours come from shared edges by `vkey` pairs, summing length. `touchesSea` /
`touchesRiver` means `area(intersect(offsetPolygons([poly], 1), water)) > 0.5`.
Breadth-first search from water-touching cells gives `hop` and `nearest` (sea wins a tie);
with no water, `hop` = BFS from site-edge cells and `nearest = 'none'`.

  - the neighbour relation is symmetric

    increases inland
  - deterministic for a seed

### Task 3: The rule table, smoothing, ponds and merging

**Files:** Create `src/stages/terrain/rules.ts` and its test.

**Interfaces:**

```ts
export type CellKind = 'flat' | 'slope' | 'hills' | 'pond';
export type FlatType = 'coastal' | 'river' | 'shelf';
export interface CellContext { cell: Cell; flatWidth: number; hilliness: number }
export interface Rule { name: string; when: (c: CellContext) => boolean; choose: (c: CellContext) => Partial<Record<Exclude<CellKind, 'pond'>, number>> }
export const TERRAIN_RULES: Rule[];                 // exactly the spec's 5 rows, in order
export interface Classified { kind: CellKind[]; flatType: (FlatType | null)[] }
export function classify(cells: Cell[], o: { flatWidth: number; hilliness: number; ponds: number }, rng: () => number): Classified;
export interface RegionGroup { kind: CellKind; flatType: FlatType | null; cells: number[] }
export function mergeRegions(cells: Cell[], c: Classified): RegionGroup[];
```

`classify` works in this order:
1. Apply the table: the first matching rule's weighted pick.
2. One smoothing pass (water-touching cells exempt).
3. Flat subtypes: coastal if nearest is sea and hop ≤ flatWidth, river if nearest is river
   and hop ≤ flatWidth, otherwise shelf.
4. Ponds: up to `ponds` flat cells, not touching sea or river and with no pond neighbour,
   chosen by rng from a shuffled eligible list.

`mergeRegions` builds connected components over the neighbour graph, with the same kind
(and, for flats, the same `flatType`). Each pond is its own group.

  - `ponds: 0` gives none
  - merged groups are connected, and no two adjacent groups share kind and flatType (except

### Task 5: Elevations and ground surfaces

**Files:** Create `src/stages/terrain/elevation.ts`, `src/stages/terrain/ground.ts` and
their tests. Install `delaunator` and `@kninnug/constrainautor`.

**Interfaces:**

```ts
// elevation.ts
export interface Levels {
  vertex: Map<string, number>;           // vkey → elevation for every cell vertex
  centre: number[];                       // per cell
  flatLevel: (number | null)[];           // per cell (flat cells)
  pondSurface: (number | null)[];         // per cell (pond cells)
}
export function computeLevels(cells: Cell[], c: Classified, groups: RegionGroup[], o: {
  relief: number; hilliness: number; flatWidth: number; course: Point2[] | null; profile: number[] | null;
  overrides: { group: number; elevation: number }[];
}, rng: () => number): Levels;
export function riverSurfaceAt(course: Point2[], profile: number[], p: Point2): number; // nearest course point
// ground.ts (terrain)
export function constrainedSurface(footprint: MultiPolygon, elevationOf: (p: Point2) => number, interior: [number, number, number][]): GroundSurface;
```

`computeLevels` follows the spec's elevation section exactly, plus the pond-bank
deviation. `maxHop` is the maximum hop over cells.

`constrainedSurface` works like this:
- gather the boundary points (elevation from `elevationOf`) and the interior points
- `new Delaunator(coords)`, then `new Constrainautor(del)`, then constrain every boundary
  edge
- keep the triangles whose centroid is in the footprint (`containsPoint`)

### Task 7: Renderer v2 with node material

**Files:** Rewrite `src/scene/renderers/terrain.ts`. Modify `src/scene/view.ts` (import
`groundHeightAt` from doc) and `cityScene.ts` if needed.

- **Ground:** one indexed BufferGeometry from all land regions' `ground`, with vertices
  deduplicated by vkey. Attributes: position, and `kind` (0 flat, 1 slope, 2 hills).
- **`MeshStandardNodeMaterial` (from `three/webgpu`, TSL nodes from `three/tsl`):**
  - `colorNode`: kind palette (v1 colours), mixed across a ragged band using
    `mx_noise_float` of world position
  - `normalNode`: bump from noise
  - `positionNode`: displacement of `±1.5 m` noise along y (≤ 2 m)
  - wet-sand tint where `positionWorld.y + noise < 1.5`
- **Water:** sea plane, river ribbon (from its `ground` boundary, at the surface per vertex),
  and ponds, in translucent node materials with a slow animated normal noise.
- Picking by point and draped outlines as before.
