# Terrain Stage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the debug stages with a real terrain stage. Water is placed first (sea,
river, ponds) along with flats; a height map is shaped around them (harmonic base plus
faded noise); and the site is divided into sea, river, pond, flat, slope and hills regions,
drawn as a lit terrain with water surfaces.

**Architecture:**
- **Pure modules under `src/stages/terrain/`:** layout (polygons), field (grid maths),
  stage (assembly). They sit on small foundation extensions: region `data`, stage
  annotations, and `overridesForStage`.
- **Renderer:** `src/scene/renderers/terrain.ts` builds the ground mesh from the height map
  and finds regions by point.

**Tech Stack:** as the foundation, plus `simplex-noise` (latest).

**Spec:** `docs/superpowers/specs/2026-11-21-terrain-design.md` (plus the foundation spec).

## Global Constraints

- Branch `terrain`. Each task ends with a commit, conventional message plus the trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Merge to `main` locally
  when done and green. No pushing.
- Heights in the height map are **metres above sea level**. Slab heights stay above-ground.
- Grid spacing is `8` m, with `cols = rows = size / 8 + 1`, and the origin at the site's
  min corner.
- North is −z, east +x, south +z, west −x.
- Every stage output still partitions its parent (`checkPartition`).
- Default terrain generation targets under 500 ms. Tests assert under 2,000 ms.
- Checks green at each task end: `npm test`, `npm run typecheck`, `npm run lint`.
- Docs ride along: `CLAUDE.md` is updated in the task that makes it wrong.
- After editing a file twice in quick succession, run `npm run dev:restart` before browser
  checks (stale Vite gotcha).

## Review Focus

1. **Extreme settings:**
   - `flats: 4` with `flatSize: 600` on a 500 m site
   - `ponds: 5` with no room
   - `relief: 20` with `hillsThreshold: 5`

   The stage must not throw. Flats may shrink or be skipped, ponds are skipped (with
   `pondsPlaced` recorded), and the partition still holds. *(Task 6 tests.)*
2. **River and shore combinations:** all 5 shore options × river on/off. The river always
   ends at the coast, or the far edge when there's no shore, and never runs uphill.
   *(Task 4 tests.)*
3. **An elevation override on a flat that no longer exists** after a reroll: dropped with
   the standard toast copy, and no crash. *(Task 6 test via the pipeline.)*
4. **Old saved debug cities:** open without throwing and show the site. *(Task 2 test:
   normalise plus a generate with unknown stage nodes.)*
5. **Site size extremes (500 and 5000 m):** grid sizes of 63 and 626 points per side.
   Generation completes; 5000 m may exceed 500 ms, and that's logged, not failed.
   *(Task 6 test.)*

### Task 3: Contour tracing and smoothing

**Files:** Create `src/grammar/contour.ts` and its test.

**Interfaces:**

```ts
export function marchingSquares(mask: Float32Array, cols: number, rows: number, level: number, origin: Point2, cell: number): MultiPolygon; // closed, nested, CCW outer
export function simplify(ring: Ring, tolerance: number): Ring;          // Douglas–Peucker, keeps closure
export function chaikin(line: Point2[], passes: number): Point2[];     // open polyline, endpoints kept
```

`marchingSquares` builds the polygons by unioning the per-cell iso-polygons through
`union` (from `clipper.ts`), which guarantees valid nesting. The mask outside the grid is
treated as 0, so shapes always close.

- [ ] **Step 1: Failing tests:**
  - a 5×5 mask with a centre 3×3 block of 1 at level 0.5 gives one polygon of area ≈ 3×3
    cells (±20 %)
  - a ring-shaped mask gives one polygon with one hole
  - `simplify` of a 100-point near-straight ring at tolerance 2 keeps ≤ 8 points
  - `chaikin` keeps both endpoints and doubles the segment count per pass, minus edges
- [ ] **Step 2: Run `npx vitest run src/grammar/contour.test.ts`.** Expected: FAIL.
- [ ] **Step 3: Implement.**

### Task 4: Water-first layout

**Files:** Create `src/stages/terrain/layout.ts` and its test.

**Interfaces:**

```ts
export type Shore = 'none' | 'north' | 'east' | 'south' | 'west';
export interface LayoutInput {
  size: number; rng: () => number; shore: Shore; coastWiggle: number;
  river: boolean; riverWidth: number; meander: number;
  flats: number; flatSize: number; ponds: number;
}
export interface Layout {
  site: MultiPolygon;
  sea: MultiPolygon | null; coastline: Point2[] | null;
  river: { polygon: MultiPolygon; course: Point2[] } | null;   // course runs source → mouth
  flats: MultiPolygon[];        // non-overlapping, clipped to land
  ponds: MultiPolygon[];        // placed only
}
export function layoutTerrain(i: LayoutInput): Layout;
export function blob(centre: Point2, radius: number, rng: () => number, irregularity?: number): MultiPolygon;
```

The rules are spec "Generation" steps 1–4 exactly: 20 % coast inset, wiggle amplitude
`coastWiggle × 15 %` of the width, source and mouth edges, Chaikin with 3 passes, flats'
first-placement and spread rules, 20 m and 30 m margins, pond radius 20–80 m, 60 m and
30 m margins, and 40 pond tries.
